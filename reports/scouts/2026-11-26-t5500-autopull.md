### 1.2 Most Likely Cause

1. **No commits landed on `origin/main` during the `21:00`–`07:00` window:**
   - The `21:00:00 EST` run on `2026-11-25` fetched and pulled `abac3275` (PR #560, merged at `20:20:19 EST`) and wrote `C:\ANTIGRAVITY\logs\autopull\autopull-20261126-020008-401-abac3275.json` (`02:00:08 UTC` = `21:00:08 EST`).
   - At every hourly run from `22:00` (`2026-11-25`) through `07:00` (`2026-11-26`), `origin/main` on GitHub was still at `abac3275`.
   - When `git fetch origin main --quiet` succeeds and `origin/main` does not move, Git does not write a new entry to `.git/logs/refs/remotes/origin/main`, and `ops/t5500/openclaw-autopull.ps1` exits at lines 528–531:
     ```powershell
     if ($OldCommit -eq $NewCommit) {
         Write-Output "SKIP: $RemoteRef is already at HEAD ($OldCommit) - nothing to do."
         exit 0
     }
     ```
   - All 25 commits between `abac3275` and `837fb5da` landed on `origin/main` **after** the `07:00:00 EST` run: 18 commits via PR #559's merge commit `ebb828e0` at `07:31:35 EST`, and 7 commits via PRs #561–#567 between `07:57:19 EST` and `07:58:58 EST`. The manual `git fetch` at `07:59:30 EST` ran 32 seconds after PR #567 was merged, and the scheduled `08:00:00 EST` run then pulled `abac3275..837fb5da`.
2. **Silent `SKIP` paths in `openclaw-autopull.ps1` + disabled `Microsoft-Windows-TaskScheduler/Operational`:**
   - Because `openclaw-autopull.ps1` only creates a file in `C:\ANTIGRAVITY\logs\autopull` after a pull happens (line 747) and writes `SKIP:` lines only to stdout (which Task Scheduler discards), and because `Microsoft-Windows-TaskScheduler/Operational` is disabled, a 10-hour quiet period with no merges on `origin/main` looks identical on disk to 10 hours of failed fetches.

2. **Why the New Posts Were Not Served Immediately After the `08:00` Pull (While PR #560's Post Was):**
   - At `08:00:06 EST` (`13:00:06Z`), `openclaw-autopull.ps1` pulled `abac3275 -> 837fb5da`.
   - For `domains/youandinotai.com/frontend`, `openclaw-autopull.ps1` takes no stop/rebuild action (`kind = 'frontend'`, `action = 'keepalive-rebuild:3200'`, `$waitForNewOwner = $false`). At `08:00:07 EST`, it immediately probed `http://192.168.0.15:3200/` and `https://youandinotai.com`, which were **still being served by the old PID `15212`** (built at `2026-11-25 21:03:21 EST` for commit `abac3275`, which included PR #560).
   - Meanwhile, `keepalive.ps1` was in the middle of pass `2535` (waiting on `obsidian` `:27123` + cloud backup probes from `08:00:15` to `08:00:56` plus its 60-second loop sleep), so `keepalive.ps1` did not reach its `frontend` probe until **`08:02:01 EST`** and did not finish rebuilding (`npm run build` -> `python build_blog_static.py && vite build`) and starting the new server (PID `19752`) until **`08:02:51 EST`**.
   - Therefore, for nearly **3 minutes after `openclaw-autopull.ps1` declared `date-app-web` `LIVE` at `08:00:07 EST`** (from `08:00:07` to `08:02:51 EST`), port `3200` served the `21:03` `dist/` build (PR #560 present; PRs #561–#567 missing and falling through to the SPA shell).
