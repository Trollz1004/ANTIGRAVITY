# Mission-Aligned Value Proposition Framework

**Status:** Active (2026-06-28)
**Owner:** CEO
**Applies to:** YouAndINotAI, Business Exchange, AI-Solutions Store, OnlineRecycle

## Executive Summary

This framework defines the product-first value propositions for ANTIGRAVITY surfaces. All customer-facing copy must sell platform access, verification, safety, and genuine connection — not non-product claims, control mechanisms, or future funding structures.

## Core Value Proposition Principles

### 1. Product-First Focus (Per BUSINESS-ONLY-PUBLIC-DOCTRINE-2026-06-22)

Customer-facing value propositions must explicitly communicate:
- **Membership value** — what users receive for their subscription
- **Verification benefits** — protection and trust features
- **Safety features** — Bot-Shield and moderation systems
- **Support access** — visible, reachable help channels
- **Uptime guarantees** — platform reliability
- **Matching quality** — real profiles and community connection

### 2. Mission Language Boundary

Mission-aligned language is:
- **"Support"** (not donate, donation, disbursement)
- **"Verified human connection"** (not charity-linked outcomes)
- **"Community-focused matching"** (not impact claims)

Mission language must never imply:
- Purchase creates control or ownership rights
- Automatic routing of funds to specific outcomes
- Investment-return or refund mechanisms
- Non-product fundraising claims

## Copy Patterns (Approved)

### Pattern: Benefit-Driven

```
[VERB] + [CONCRETE OUTCOME] + [PLATFORM GUARANTEE]

Examples:
"Connect with verified members. Bot-Shield ensures real humans only."
"Access premium events. Founder pricing never increases."
```

### Pattern: Trust-First

```
[TRUST SIGNAL] + [PLATFORM PROMISE] + [SUPPORT BACKSTOP]

Examples:
"Multi-factor verification protects every account. Square secures payments. Support is always reachable."
"Real profiles only. We verify because anonymity enables abuse. Help is one click away."
```

## Copy Anti-Patterns (Prohibited)

| Prohibited | Reason | Alternative |
|------------|--------|-------------|
| "Donate"/"Donation" | Violates Florida §496.405 | "Support" |
| "Contractual revenue disbursement" | Non-product legal claim | "Platform access" |
| "Solicitation" | Legal violation | "Invite" |
| Control-rights claims | Creates purchase friction | "Verified access" |
| Automatic routing promises | Unverified automation claim | "Purchase grants access" |
| Investment-return language | Misleads on purchase nature | "Subscription value" |

## Compliance Implementation

### For Frontend Developers

1. All CTAs must link to verifiable platform features
2. Pricing pages must show actual product access terms
3. Support links must be visible above-the-fold
4. No hidden legal claims in tooltips or modals

### For Support Agents

1. Refund policy references: "See refund terms in your receipt"
2. Verification questions: "Bot-Shield protects all verified members"
3. Account issues: "Support can verify your identity manually"
4. Payment questions: "Square handles checkout and receipts"

### For Marketing Agents

1. Ad copy must link to live product pages
2. Social posts must lead to signup or features
3. Email subject lines must reflect platform value
4. No implied future benefits or external claims
