## 2. Official Repositories, Model Weights, and Exact Licences

The name "Matrix" in recent world-model research refers to **two separate research lineages** from two different organizations, plus a related 3D scene generator from Skywork AI. Their open-source availability and commercial licensing differ sharply.

### A. 'The Matrix: Infinite-Horizon World Generation with Real-Time Moving Control' (Alibaba Tongyi Lab, HKU, Waterloo, Vector Institute — `arXiv:2412.03568`)

- **Paper and Project Showcase:** Published December 4, 2024 by Ruili Feng, Han Zhang, Zhantao Yang, Jie Xiao, Zhilei Shu, Zhiheng Liu, Andy Zheng, Yukun Huang, Yu Liu, and Hongyang Zhang ([arXiv:2412.03568](https://arxiv.org/abs/2412.03568); [Project Page](https://thematrix1999.github.io/index.html); [GitHub Showcase Repo](https://github.com/TheMatrix1999/thematrix1999.github.io)).
- **Architecture and Training Data:** A `2.7B`-parameter video world simulator (`2.3B` Diffusion Transformer backbone + `0.4B` Interactive Module) using a Shift-Window Denoising Process Model (`Swin-DPM`) and a 4-step Stream Consistency Model (`SCM`) ([arXiv:2412.03568 §3–§4](https://arxiv.org/html/2412.03568v1)). It was trained on `1,200,000` labeled 6-second clips from *Forza Horizon 5* and `1,000,000` clips from *Cyberpunk 2077* captured via Cheat Engine, ReShade, and OBS, combined with unlabeled real-world footage ([arXiv:2412.03568 §3.2 & Appendix B](https://arxiv.org/html/2412.03568v1)).
- **Code and Model Weights Status:** **Unreleased.** Although the abstract of [arXiv:2412.03568](https://arxiv.org/abs/2412.03568) stated that *"All the codes, data, and model checkpoints in this paper will be open sourced,"* the official GitHub account [`TheMatrix1999`](https://github.com/TheMatrix1999) contains only the static showcase repository [`TheMatrix1999/thematrix1999.github.io`](https://github.com/TheMatrix1999/thematrix1999.github.io) (last pushed November 25, 2024, containing pre-rendered `.mp4` demos). As noted by commenters in the 210-point Hacker News thread ([HN Item #42201117](https://news.ycombinator.com/item?id=42201117)), even the interactive demo buttons on the showcase page only play static video files.
- **Exact Licences and Commercial Usability:**
  - **Paper Text:** Licensed under **Creative Commons Attribution 4.0 International (`CC BY 4.0`)** ([arXiv:2412.03568](https://arxiv.org/abs/2412.03568)).
  - **Code and Model Weights:** **No open-source licence (`license: null` / All Rights Reserved)** on [`TheMatrix1999/thematrix1999.github.io`](https://api.github.com/repos/TheMatrix1999/thematrix1999.github.io), and no weights exist to license. **Commercial use is not possible.**

## 3. Hardware Needed to Run in Real Time

None of the Matrix world models can run in real time on consumer browser hardware, nor can they run in real time on our local fleet nodes (**Alienware** has an `8 GB` VRAM NVIDIA GeForce RTX 3070 per `docs/standards/ALIENWARE-SOUL.md`, and **Sabretooth** has a `16 GB` VRAM AMD Radeon RX 6800 with no CUDA support per `docs/standards/SABRETOOTH-SOUL.md`):

- **'The Matrix' (`arXiv:2412.03568`, `2.7B` parameters):**
  - **Resolution and Speed:** `1280x720` (`720p`) at `8 to 16 FPS` (`0.8 FPS` before `SCM` consistency distillation) ([arXiv:2412.03568 Table 2](https://arxiv.org/html/2412.03568v1)).
  - **Required Hardware:** Distributed across **8 data-center GPUs (`8x NVIDIA A100 80 GB`)** using `bfloat16` mixed precision and DeepSpeed Ulysses sequence parallelism ([arXiv:2412.03568 Appendix A.2](https://arxiv.org/html/2412.03568v1)).

- **Matrix-Game 2.0 (`arXiv:2508.13009`, `1.8B` parameters):**
  - **Resolution and Speed:** `352x640` at `25 FPS` using 3 denoising steps, `Wan2.1-VAE` caching, and a 6-frame rolling KV-cache ([arXiv:2508.13009 §5.1 & §5.3](https://arxiv.org/html/2508.13009v5)). On October 23, 2026, an independent benchmark ([GitHub Issue #96](https://github.com/SkyworkAI/Matrix-Game/issues/96), [`kkjcodes/liveframe`](https://github.com/kkjcodes/liveframe/tree/main/agent/world/evidence/m7-mg2-h100)) reproduced `19.7 FPS` median (`19.6 FPS` mean) across 24 test cases on a single H100 GPU.
  - **Required Hardware:** Linux OS, `64 GB` system RAM, FlashAttention, and an **NVIDIA GPU with at least `24 GB` VRAM (`NVIDIA A100 80 GB` or `NVIDIA H100 80 GB` tested)** ([`Matrix-Game-2/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-2/README.md)).

- **Matrix-Game 3.0 (`5B` distilled model):**
  - **Resolution and Speed:** `704x1280` (`720p`) at up to `40 FPS` using 3 inference steps, INT8 quantization (`--use_int8`), FlashAttention-3 (`--fa_version 3`), and a pruned `mg_lightvae_v2` decoder ([`Matrix-Game-3/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-3/README.md)).
  - **Required Hardware:** Linux OS, `64 GB` system RAM, and **NVIDIA Hopper/Ampere data-center GPUs (`H100` / `A100`, single- or multi-GPU FSDP with `--use_async_vae`)** ([`Matrix-Game-3/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-3/README.md)).

- **Matrix-Game 4.0 (`arXiv:2610.27999`, `5,001,016,512` BF16 parameters per scene checkpoint):**
  - **Resolution, Disk, and OS Requirements:** Generates `864x480` RGB frames in 4-frame latent chunks (`1` denoising step with `TAEHV` for `realtime`, or `2` steps with `Wan2.2_VAE` for `quality`). Requires Linux, Python 3.12, PyTorch 2.12.0 built for **CUDA 13.2**, and **`44.2 GB` of disk space** for the three scene checkpoints (`~10 GB` each) plus shared `umT5-xxl` and `Wan2.2` codecs ([`Matrix-Game-4/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/README.md); [`Matrix-Game-4/releases/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/releases/README.md)).
  - **Measured Single-GPU Hardware Presets (`864x480` steady state, 1 active session per server process):**
    - **`NVIDIA GeForce RTX 5090 (32 GB VRAM)`:** Reaches `60 FPS` online gameplay with `112 ms` key-press-to-display latency (`23 ms` to first reacting frame, `10 ms` per 4-frame chunk) and up to **`83 FPS`** steady-state model throughput using FP8 block linears and CUDA graphs at **`18.2 GiB` peak GPU memory** ([arXiv:2610.27999](https://arxiv.org/abs/2610.27999); [Project Page](https://matrix-game-v4-0.github.io/page/)).
    - **`NVIDIA GeForce RTX 5080 (16 GB VRAM)`:** Fixed-prompt mode only (unloads `umT5-xxl` before loading the DiT). Reaches **`~42 FPS` at `~9.6 GB` VRAM** (`--preset rtx5080`) or **`~67 FPS` at `~12.8 GB` VRAM** with patched SageAttention 2.2.0 (`--preset rtx5080-sage`) ([`Matrix-Game-4/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/README.md#rtx-5080)).
    - **`NVIDIA GeForce RTX 5070 Ti (16 GB VRAM)`:** Fixed-prompt mode with uncalibrated W8A8 INT8 block linears. Reaches **`~41 FPS` at `~9.2 GB` VRAM** (`--preset rtx5070ti`) or **`~58 FPS` at `~10.9 GB` VRAM** with SageAttention (`--preset rtx5070ti-sage`) ([`Matrix-Game-4/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/README.md#rtx-5070-ti)).
    - **`NVIDIA A100-SXM4-80GB`:** Reaches **`~38 to 39 FPS`** in fixed-prompt mode (`Castle` / `Ancient Egypt`) and **`~28.9 FPS`** in dynamic-prompt mode (`City Racing`) ([`Matrix-Game-4/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/README.md#a100-performance)).
    - **Older Consumer GPUs (`RTX 4090`, `RTX 3090`, `RTX 3070`):** Dedicated presets exist only for `A100`, `RTX 5090`, `RTX 5080`, and `RTX 5070 Ti`. Community requests for `RTX 4090` ([Issue #92](https://github.com/SkyworkAI/Matrix-Game/issues/92)) and `RTX 3090` ([Issue #93](https://github.com/SkyworkAI/Matrix-Game/issues/93)) opened on October 18, 2026 remain unanswered, and an `8 GB` card like Alienware's `RTX 3070` falls short of even the `9.2 GB` INT8 minimum.

## 4. What Changed in the Last 30 Days (`2026-10-10` to `2026-11-09`)

While `'The Matrix'` (`arXiv:2412.03568`) has had zero repository commits since November 25, 2024 ([`TheMatrix1999/thematrix1999.github.io`](https://github.com/TheMatrix1999/thematrix1999.github.io)), [`SkyworkAI/Matrix-Game`](https://github.com/SkyworkAI/Matrix-Game/commits/main) underwent a major architectural shift in the last 30 days:

- **October 14–15, 2026 — Public Release of Matrix-Game 4.0 (`Streaming Neural Rendering for Playable Games`):** Skywork AI released `Matrix-Game 4.0` ([commit `b65d0cae`](https://github.com/SkyworkAI/Matrix-Game/commit/b65d0cae)) and its `44.2 GB` Hugging Face checkpoint/asset bundle ([`Skywork/Matrix-Game-4.0`](https://huggingface.co/Skywork/Matrix-Game-4.0)). Crucially, Skywork abandoned pure pixel-only world modeling (where the video model tries to hallucinate physics and game rules) because objects disappear when leaving the camera view and game state drifts ([Project Page](https://matrix-game-v4-0.github.io/page/)). Instead, Matrix-Game 4.0 puts an **executable C++20/SDL2/Jolt Physics game engine** in charge of state, collisions, HUD, audio, and rules, renders a cheap low-poly RGB proxy frame, and uses the 5B causal video model solely as a neural post-processor over WebRTC ([`Matrix-Game-4/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/README.md)).
- **October 15–16, 2026 — Consumer Blackwell GPU Presets (`RTX 5090`, `RTX 5080`, `RTX 5070 Ti`) and `arXiv:2610.27999`:** Skywork landed FP8/INT8 single-GPU inference runtimes for `RTX 5090` ([commit `5446525c`](https://github.com/SkyworkAI/Matrix-Game/commit/5446525c)), `RTX 5080` ([commit `2f49bc38`](https://github.com/SkyworkAI/Matrix-Game/commit/2f49bc38)), and `RTX 5070 Ti` ([commit `56c61df7`](https://github.com/SkyworkAI/Matrix-Game/commit/56c61df7)), and published the technical report *"Matrix-Game 4.0: Harnessing Video Models for Real-Time Playable Game Worlds"* ([arXiv:2610.27999](https://arxiv.org/abs/2610.27999); [commit `3aaed99c`](https://github.com/SkyworkAI/Matrix-Game/commit/3aaed99c)).
- **October 16, 2026 — INT8 Quantization Rounding Bug Reported:** Community audit reported in [Issue #90](https://github.com/SkyworkAI/Matrix-Game/issues/90) that `int8_quantize_kernel` in the `RTX 5070 Ti` W8A8 path truncates toward zero instead of rounding because the `±0.5` offset is cast to `int8` before addition.

### Candidate Approaches and Trade-Offs

- **Candidate (a) — Internal Team-Only Study Tool (Concept Flythroughs & Clean-Room Architecture Study):**
  - **How it works:** Treat the Matrix papers (`arXiv:2508.13009`, `arXiv:2610.27999`) and repo (`SkyworkAI/Matrix-Game`) strictly as an internal design and research reference for the team. Specifically, study how Matrix-Game 4.0 couples a deterministic C++/physics harness and structured scene-state captions with a coding agent, and optionally inspect pre-published or offline-generated concept flythroughs solely to judge camera framing, horizon lines, and mood before building real 3D geometry in `src/engine/`. Zero Matrix code, weights, or generated pixels ever enter the game repository, asset pipeline, or public marketing.
  - **Pros:** `100%` compliant with every hard rule; `$0` cloud GPU spend; zero risk of non-commercial or training-data taint in shipped assets; preserves 100% clean-room ownership under `remake` (`100% Yours`) and `reverse-engineer-anything` (`rea`).
  - **Cons:** Does not automatically produce shippable 3D meshes or textures (which still must be authored cleanly through our in-house `src/engine/` and `cli-anything-blender` pipeline).

- **Candidate (b) — Offline Generation of Reference Footage or Textures for Our Own Artists:**
  - **How it works:** Run `Matrix-Game 2.0/3.0/4.0` or `Matrix-3D` offline to generate video clips or texture sheets that our artists or `cli-anything` scripts bake into DREAM Online zones.
  - **Pros:** Could provide rough moodboards or motion studies if we had an idle `24 GB+` CUDA card.
  - **Cons:** First, `Matrix-3D` is **strictly disqualified** from any shipped pipeline because it depends on non-commercial licenses (`FLUX.1 [dev] Non-Commercial License`, `NVIDIA Source Code License-NC`, `Inria Gaussian-Splatting Non-Commercial License`, and `S-Lab License 1.0`). Second, `Matrix-Game 2.0/3.0/4.0` outputs temporal video frames (`352x640` to `864x480` compressed `.mp4` streams with view-dependent lighting baked in), which make poor tileable PBR textures (albedo/normal/roughness) compared to procedural/Blender authoring. Third, neither Alienware (`8 GB` CUDA) nor Sabretooth (`16 GB` AMD, no CUDA) can run `Matrix-Game 2.0/3.0/4.0` natively without cloud GPU rental, violating `$0` marginal spend.

- **Candidate (c) — Runtime Execution in the Player's Browser (or Streamed to the Browser):**
  - **How it works:** Attempt to run a Matrix world model in the player's browser via WebGPU/WASM, or stream neural-rendered frames from a server to the player's browser (`Matrix-Game 4.0` WebRTC mode).
  - **Honest Technical Verdict — Completely Infeasible and Architectural Downgrade:**
    1. **Browser Hardware Limits:** A `5B`-parameter BF16 diffusion transformer (`~10 GB` scene weights + `umT5-xxl` + `Wan2.2 VAE` / `TAEHV`, totaling `44.2 GB` on disk and `9.2 GB` to `18.2 GiB` active VRAM) requiring CUDA 13.2 FP8/INT8 custom Triton kernels and patched SageAttention cannot download or execute at `40–60 FPS` inside a player's browser WebGPU context on consumer laptops, phones, or integrated GPUs.
    2. **Server Streaming Cost Explosion:** Matrix-Game 4.0's "browser demo" does **not** run the model in the browser; it runs one dedicated `RTX 5090` / `A100` Linux server per single active player (`"Only one active game session and one scene model per server process are supported"`, [`Matrix-Game-4/README.md`](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/README.md#layout)) and streams `864x480` video over WebRTC. For a free-to-play MMORPG, dedicating a `$2,000–$15,000` GPU to every concurrent player would bankrupt the studio instantly.
    3. **Multiplayer & Engine Superiority:** Our in-house WebGPU engine (`src/engine/`) renders true 3D geometry locally on the player's own device at native resolution (`1080p/4K`), supports shared multiplayer state across all four DREAM Online zones, and costs `$0` per player hour in server GPU compute.

### Selected Recommendation

**Pick Candidate (a) — Internal Team-Only Study Tool.** We keep `Matrix-Game` strictly as an internal research reference (studying Matrix-Game 4.0's separation of deterministic engine state and coding-agent rule authoring via clean-room `rea` specs, and using concept flythroughs only for internal layout/camera study) while keeping `100%` of DREAM Online's runtime rendering, physics, and shipped assets inside our in-house WebGPU engine (`src/engine/`). This costs `$0`, avoids every hardware bottleneck (`8 GB` RTX 3070 limit) and non-commercial license trap (`Matrix-3D` / Maestro rule), and guarantees that every frame shown to backers is 100% real footage from our own build.
