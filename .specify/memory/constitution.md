# ANTIGRAVITY Constitution

## Core Principles

### I. One Repo, Main Only
`C:\ANTIGRAVITY` is the sole canonical working tree. All work lands on `main`. Backup clones, exported folders, and old node topology are non-executable evidence, never instructions.

### II. Judge-Gated Delivery
The judge lane alone pushes, merges, or deletes branches, unless Joshua directly authorizes an exception in the moment. Every other lane — Hermes, OpenClaw, OpenCode, Sonnet workers — proposes; it does not deliver.

### III. Business-Only Customer Copy
Public product surfaces carry business framing only. Internal governance, owner decisions, and non-product context stay out of customer-facing text. The restricted-word list is enforced mechanically by the commit guard on every staged file, not left to review discretion.

### IV. No Keys In Code Or Client
No provider key, token, or credential ever lands in source or ships to a browser. OmniRoute is the only model gateway a harness calls, with the key held server-side. Claude never routes through OmniRoute — it uses its own account authentication.

### V. Identity Over Ports
A service is reported UP only after an identity probe confirms it is the expected service, never from a port answering or a status code alone. Acceptable states: UP, DOWN, WRONG SERVICE, AUTH MISSING, AUTH REJECTED, NOT CONFIGURED.

### VI. Right Model For The Work
Sonnet agents carry out mechanical work: scaffolding, panels, tests, routine fixes. Fable drafts rulings, product design, and anything customer-voiced.

### VII. Tests Ship With The Feature (NON-NEGOTIABLE)
Every panel and feature ships with vitest tests in `tests/*.test.js` before it counts as done. A phase is complete only when its tests pass and the House one-pass reports the service UP.

### VIII. Recorded Numbers Only
Every number shown anywhere carries its source and is a live or logged reading. No projections, no placeholders dressed as data, no sample rows in a production path.

## Product Boundaries

The date app is frozen and listed for sale; work on it is keep-alive only — no new features, no redesign. DREAM Online is the active game project and runs on the Alienware node's hardware. JARVIS is the one Mission Control; any new operational view is a JARVIS panel, never a second dashboard.

## Development Workflow

Non-trivial work starts from a written spec under `specs/<feature>/` — `spec.md`, `plan.md`, `tasks.md` — so a session begins from stated intent and a task list instead of re-deriving it from conversation. Relative URLs only in any browser client; every external source is proxied server-side. No emoji, no purple, house glass tokens and Lucide icons in UI work.

## Governance

This constitution supersedes ad hoc practice, amended by editing this file through the judge lane's normal review, never by a sweep that deletes the words it defines. `CLAUDE.md` carries fuller operating history; where the two conflict on a standing ruling, the most recently dated ruling in `CLAUDE.md` controls until this file is updated to match.
