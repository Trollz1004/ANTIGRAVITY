# THE WHEEL — Hermes CEO standing order

> Updated 2026-07-03 by Joshua directive.
> The Wheel is now a Hermes-owned visibility loop, not a multi-agent staffing mandate.

## Purpose

Paperclip exists so Josh can see the work being done. Hermes does the work; Paperclip shows timestamped organization:

- tasks
- routines
- issues
- goals
- blockers/fixes
- evidence and verification
- done history

## Active owner

Hermes CEO is the only required active Paperclip agent.

FCC-Claude may be used as an optional browser-visible helper when Josh explicitly wants it, but it does not become a separate standing CEO unless Josh says so. Hermes/Opus monitor and verify its work.

## Loop

At each work cycle, Hermes should:

1. Read the active Josh instruction and current repo/Paperclip state.
2. Create or update the visible Paperclip row/card for the work.
3. Load the smallest needed `.agents/skills/*/SKILL.md` department skill.
4. Use built-in APIs/tools/browser/localhost surfaces as needed.
5. Spawn temporary subagents only when parallel hands materially help.
6. Fix blockers directly when safe; otherwise record the exact blocker and next action.
7. Verify real output, not just 200 OK or worker claims.
8. Timestamp the result in Paperclip as done/blocked/routine/issue/goal.

## Queue law

No filler queue. No fake 100-task backlog.

Keep only useful visible rows:

- NOW: work Hermes is actively doing.
- NEXT: concrete ready tasks Josh/Hermes actually intend to execute.
- ROUTINES: recurring checks with last/next fire.
- ISSUES: blockers/repairs with owner and timestamp.
- GOALS: persistent outcomes and current next step.
- DONE: verified completions.

## Escalation

Only escalate to Josh for:

- credentials only he holds
- money/legal/production authority
- doctrine/payment/public-copy decisions
- repeated same-cause failure after autonomous repair attempts

Everything else: Hermes resolves, delegates temporarily, or records the blocker with evidence.

## ChatPlayground / browser AI cockpit

ChatPlayground can be used by Hermes as a browser/localhost resource for model comparison, drafting, or review. It does not need an API relay. Paperclip should show “Hermes used ChatPlayground” as part of the task evidence when relevant.
