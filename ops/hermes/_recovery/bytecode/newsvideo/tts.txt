## docstrings

<module>:
Voiceover generation with a pluggable backend.

Backends, in preference order:
  edge      -- Microsoft Edge read-aloud neural voices via the `edge-tts` package.
               Free, no credential, no account; the same neural voices Azure sells.
               Needs network and a `pip install edge-tts` (see TRO-9).
  omniroute -- POST {base}/audio/speech. The sanctioned path per the original task
               spec. Currently unusable: every speech route lacks a credential
               (google 401, openai/elevenlabs "no credentials"), re-probed 2026-09-09.
  sapi      -- Windows System.Speech (local, offline, no spend). Real synthesis,
               not a placeholder, but a plainer voice than a hosted model. This is
               what video #1 shipped with and it remains the fallback.

No backend ever writes a silent or fabricated file. If synthesis fails the
caller gets an exception and the segment is reported UNVERIFIED upstream.


  TTSError:
TTSError

  Clip:
Clip

  omniroute_available:
Probe the speech endpoint with a one-word request. Returns (ok, detail).

  synth_sapi_batch:
Synthesize many segments in one PowerShell session.

Batched because a cold System.Speech load costs ~1s; the backlog needs 126 clips.


  edge_available:
Is the edge backend usable right now? Returns (ok, detail).

  synth_edge_batch:
Synthesize many segments through Edge neural TTS, one event loop for all.

`rate` is a percentage string ("+10%"). Neural reads run roughly 15% longer
than SAPI at rate 0 because the pacing is natural; raise it if a day folder
has to fit a duration budget.

Writes .wav in the pipeline's format regardless of the `out` suffix given, so
it drops in wherever synth_sapi_batch was used.
