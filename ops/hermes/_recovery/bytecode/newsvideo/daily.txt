## docstrings

<module>:
The unattended daily run: source -> day folder -> voice -> visuals -> mp4 ->
thumbnail -> upload -> summary.

One process, one exit code, one packet. Every stage is verified against the file
it claims to have written (see gates.py) before the next stage is allowed to
start, so the chain stops at the first broken artifact instead of carrying it
forward and shipping a 0-byte mp4.

Exit codes -- Task Scheduler shows these as the "Last Run Result", so they are
the first thing the user sees without opening a log:
    0  video produced and (if upload was armed) shipped
    2  a stage or a gate failed -- nothing shipped, see the packet
    3  video produced and verified, but upload is not armed yet (no credentials)
    4  bad invocation / environment (no ffmpeg, no day folder, ...)

Usage
    python -m newsvideo.daily                 # yesterday, upload if credentials exist
    python -m newsvideo.daily --date 20260901 --no-source
    python -m newsvideo.daily --upload off    # render and verify only


  Run:
Run

      <genexpr>:
status

  stage_source:
Fetch yesterday's stories and land them in the repo day folder.

The generator writes to the runtime root; the repo day folder is the source of
truth for everything downstream, so the files are copied across and verified
here rather than trusted.


  pick_backend:
Best voice that will actually speak this morning, probed in preference order:
OmniRoute (the sanctioned gateway), then edge neural, then local SAPI.

Never a placeholder: if none of them speaks, the run fails rather than muxing
silence, and the summary names the engine that did.


  stage_verify:
The gate wall. Everything shipped downstream has been through here.

  PreflightError:
PreflightError

  show_status:
What went out on each of the last `days` mornings, from the packets.

This is the check for "three consecutive mornings, zero human input": a
morning with no packet is a morning the chain did not run at all, which is
otherwise indistinguishable from silence.
